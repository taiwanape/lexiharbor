# LexiHarbor 重新規劃

更新：2026-09-07。基準：`624578b`。本文件記錄這次重新檢查後的決策；下列開發項目尚未視為完成。

本次交付：現有程式審查、基本測試、候選資料來源查核與重新規劃。階段 A 的資料小樣與品質實測是下一個開發工作。

## 給使用者的版本

保留能用的手機介面框架，重新做詞庫、查字和複習核心。現有版本是展示原型，尚不適合收費銷售。

順序是：確認可商用的繁中內容 → 完成可實用的查字與學習 → 手機試用 → 收費上架。

現在不需要使用者設定服務或付費。下一次需要使用者動手時，只提供當下的一個步驟。

## 1. 產品與重做範圍

目標是供繁體中文使用者學英文的 Android 字典：能找到意思、聽發音、收藏、複習，並可逐步發展成可銷售產品。參考產品的公開功能清單只用於確認需求；品牌、畫面與內容獨立製作。

| 部分 | 決策 | 原因 |
| --- | --- | --- |
| React Native / Expo / TypeScript | 保留 | 能支援 Android 與網頁預覽；目前型別檢查通過，沒有換框架的證據 |
| 配色、圖示、一般介面元件 | 保留作起點 | 可重用；手機版面、可操作性與品牌名稱仍須驗收 |
| 12 筆詞條的陣列與搜尋 | 重做 | 規模、詞形、排序、多義詞及內容來源管理不足 |
| 複習和學習紀錄 | 重做 | 目前未排程，日期統計不正確 |
| 收藏、詳情與設定連接 | 補齊並重整 | 有入口不能操作；詳情不應只存在查字頁 |
| 收費介面 | 重新決定後實作 | 目前展示的完整詞庫、複習與商品均未驗證 |
| 現有 GitHub 試用版 | 作為舊原型參考 | 新版通過對應驗收後才更新；本次沒有變更線上部署 |

不必砍掉整個專案或改用另一套框架。先建立清楚的資料與服務邊界，再逐項替換核心。

## 3. 詞庫：先確認資料用途，再匯入

正式的繁中英漢內容是目前最重要的未完成項目。英文 WordNet 加上中文反向搜尋，並不自動成為完整英漢學習字典。

| 候選 | 可提供什麼 | 決策 |
| --- | --- | --- |
| Princeton WordNet 3.0 | 英文詞義、同義詞、詞形資料；部分義項有例句 | 英文核心優先候選；保留完整授權，固定版本 |
| Open English WordNet | 更新的英文詞義網路 | 英文核心備選；保留 PWN 與新增資料的授權；不與 PWN 舊義項 ID 直接混接 |
| CC-CEDICT | 繁簡中文詞、拼音與英文解釋 | 先評估漢英與英文反查；目前官方採 CC BY-SA 4.0，資料再散布與修改須按條款處理 |
| Chinese Open Wordnet | 對齊 PWN 3.0 的中文詞形 | 暫列研究候選；簡體詞形不等於繁中釋義，上游授權差異尚待釐清 |
| ECDICT／來源混合的英漢 CSV | 可能包含大量中文翻譯 | 未完成逐來源確認前不納入正式資料；repo 的 MIT 標籤不足以代表所有內容來源 |

PWN 的官方授權明確允許免權利金商用。CC-CEDICT 官方也允許商用，但要求署名及符合相同方式分享條件。免費指資料授權，不代表中文編校、主機、商店或任何未來 API 都零成本。詳見 [資料來源與授權](DATA_LICENSES.md)。

### 下一個具體工作：資料小樣與品質評估

1. 從供應者正式提供的下載檔取得固定版本；保留原檔、完整授權、來源 URL、日期與 SHA-256。使用 CC-CEDICT 時採已發布版本，不採未審核即時資料。
2. 自訂 300 個測試查詢，涵蓋常用名詞、動詞、多義詞、屈折變化、片語、繁中反查與查無結果；這是我們的測試集合，不冒称標準高頻詞表。
3. 以 `apple`、`bank`、`run`、`went`、`take off`、`好奇` 等查詢實測。記錄「找得到」和「意思正確」兩種結果；反查英文解釋命中不得冒充中文義項對照。
4. 產出資料樣本、覆蓋率、已知缺漏及實際授權頁。先作小規模試用，合格後再擴大；不先承諾 30 萬詞或某個大詞數。
5. 完整英漢中文釋義若仍不足，先為小樣獨立編寫並校訂。未來擴充需另有可再散布的來源或持續編校；不得把大量未校對文字直接作正式字典。

資料准入條件：來源和條款可追溯；資料方向與畫面標示一致；試用收錄的主要義項已逐項檢查；缺失音標、例句或等級可留空，不編造 CEFR、真人錄音或完整收錄宣稱。

CC-CEDICT 衍生資料與獨立編寫內容分開管理；凡構成其改作的資料仍須依授權處理，分檔本身不能免除義務。正式發布前備妥適用的可取得資料版本與署名，不把 CC-BY-SA 簡化成「整個 App 必須開源」或「只加一句來源就夠」。

## 4. 開發順序與完成標準

| 階段 | 交付 | 通過標準 | 使用者現在要做什麼 |
| --- | --- | --- | --- |
| A：資料驗證 | 固定來源、小樣、來源清單、品質報告 | 上述資料准入條件通過，中文不足部分明確列出 | 不需操作 |
| B：實用試用版 | 查字、詳情、收藏、發音、日期正確的複習；網頁＋Android 測試版 | 查字→收藏→複習→重開仍保留；Android 飛航模式可查；所有可點入口有作用 | 收到連結／安裝檔後試用 |
| C：正式內容與手機品質 | 擴大核准資料、穩定的離線資料庫、錯誤恢復與匯出 | 常用查詢品質、效能、字體放大、儲存遷移與裝置測試通過 | 只提供試用回饋；必要時協助真機驗證 |
| D：銷售發行 | 選定販售方式、正式 AAB、商店內容與測試發行 | 商品／下載權限與重裝測試通過，完成適用商店測試與審核 | 到這一步才處理本人帳號驗證、售價與付款資料 |

先完成四個主要入口：查字、單字本、複習、設定。情境會話可沿用作下一批內容；整段翻譯、語音輸入、文法練習、小工具等原需求延後逐項補齊。它們沒有被視為已完成，也不列入第一個收費版本的宣稱，除非已各自驗收。

## 5. 核心設計

### 資料與搜尋

- 共用的詞條與搜尋介面，Android 使用 SQLite 索引；網頁試用先使用獨立的輕量資料實作，避免強迫 GitHub Pages 承擔 SQLite Web 的額外部署條件。
- Expo 官方目前將 SQLite Web 支援列為 alpha，且需要 WebAssembly 與特定 HTTP headers，因此不能只將手機資料庫套件匯入網頁就宣稱雙端完成。[Expo SQLite](https://docs.expo.dev/versions/latest/sdk/sqlite/)
- 詞條、義項、詞形、翻譯關聯、發音與例句分開。每個外部內容能追到來源版本與授權；中文關聯詞、中文釋義與自行編校文字應能區別。
- 搜尋排序：完全符合 → 合法詞形還原 → 前綴 → 相關候選。中文使用獨立索引與斷詞策略，不假設英文全文索引自動適合中文。
- 結果分頁、限制一次顯示數量；英文大小寫、空白、連字號與多詞片語有明確處理。搜尋輸入使用參數化查詢。
- 缺少義項或例句時顯示可用內容，空資料庫也能進入明確的空狀態。資料更新不覆寫使用者收藏。

### 收藏、複習與儲存

- 以穩定詞條／義項 ID 關聯收藏與複習，不以畫面位置或全部詞庫的索引當身分。
- 每筆複習保存時間、評分、下次到期時間；首版採可解釋、可測試的規則。畫面顯示的下次間隔由實際排程取得。
- 學習統計由真實紀錄計算。本地日期跨月、跨年、斷日、當天超過 10 次與重新開啟皆有測試。
- 深色模式保存偏好，可跟隨系統；讀取完成前防止新操作被舊資料覆蓋。儲存有格式驗證、序列化寫入、版本遷移及錯誤提示。
- 遷移時保留原始備份與可辨識的舊收藏／歷史。舊版沒有真實時間明細的累計不能捏造成每日紀錄或精確複習排程；在版本說明中交代統計重新起算的部分。
- 提供單字本與學習資料匯出／匯入，讓無帳號版仍能轉移資料。

### 發音與介面

- 使用系統文字轉語音，列出裝置實際可用的英語 voice；能否離線與英美口音須在 Android 驗證，缺語音包時給出可操作的說明。
- 語音輸入未實作前不顯示麥克風按鈕。未完成提醒前不顯示已設定晚上 8 點。
- 查字、收藏、歷史共用詳情頁，支援返回、長單字與大字體；新裝首次畫面顯示真實空紀錄。
- 試用階段清楚標示試用與收錄範圍；收費入口等商品和功能驗證後才提供。

## 6. 收費與試用決策

建議首發採「Google Play 一次付費下載」，並另外提供免費網頁／測試版體驗。這符合使用者先試用、之後可銷售的目標，也可避免第一版依賴 RevenueCat 的額外訂閱管理服務。這是規劃建議，尚未建立或變更任何商店商品。

現有 RevenueCat 程式列為待替換的試驗性接線，不是必要基礎。若最終選擇免費下載加內購，另行完成原生收款、驗證、恢復、退款、離線與商品類型處理；移除 RevenueCat 並不代表這些工作自動消失。

| 成本 | 規劃 |
| --- | --- |
| 合規使用的 PWN／CC-CEDICT 固定資料版本 | 無資料授權權利金；有保留聲明／資料分享等條件 |
| 繁中編寫、校訂與更新 | 仍有工作成本；需付費採購或聘人時提供具體內容與報價再決定 |
| 字典查詢伺服器、雲端翻譯、廣告服務 | 首版核心設計不需要；將來加入再評估 |
| RevenueCat | 一次付費下載方案不需要啟用 |
| Google Play | 帳號與銷售費用按官方適用條款；不承諾整個營運零成本 |
| 網頁／建置服務 | 免費方案限制與未來價格獨立評估；不預先啟用付費方案 |

Google Play 已提供為免費下載的同一 App 不能直接改成付費下載，因此正式套件的免費／付費決策要在商店發布前完成。GitHub 網頁預覽不等於把 Android 正式套件設為免費。[Google Play 定價](https://support.google.com/googleplay/android-developer/answer/6334373?hl=en)

GitHub Pages 用於目前的展示預覽；不把它規劃成收款網站或商業 SaaS 主機。原始碼是否維持公開，與試用成品的公開是不同決策；正式商業化前可規劃私人原始碼和分開的公開展示，但本次不更改 GitHub 能見度。[GitHub Pages 限制](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits)

## 7. 實際上架驗收

這些項目由開發進度推進，不一次要求使用者自行處理整份清單。

- 先核准資料品質，再補齊授權頁、隱私頁與公開支援方式。商店文案只列已完成且可驗證的功能。
- 品牌名稱目前暫用 LexiHarbor；正式發布前核對名稱與商店畫面。獨立開發不等於已經完成商標檢索或法律審查。
- 鎖定相容版本；產生 Android APK 供測試、AAB 供商店。檢查實際構建的 target SDK、簽章、安裝與升級，不能以 `app.json` 或 build profile 的存在代替驗證。
- 2026-08-31 起一般手機新 App／更新的 target API 要求為 Android 16／API 36 或以上；提交前再核對。[Android 官方](https://developer.android.com/google/play/requirements/target-sdk)
- 2023-11-13 後建立的個人開發者帳號，官方目前要求至少 12 人連續參與 14 天封閉測試後申請正式版權限。使用者帳號類型及資格尚未確認；不是每個帳號都一律套用，也不保證第 14 天立即上架。[Google 官方測試規定](https://support.google.com/googleplay/android-developer/answer/14151465?hl=zh-Hant)
- 對候選 Android 裝置訂定效能驗收：離線查詢熱啟動結果 p95 目標低於 200ms、首屏可操作目標低於 3 秒；這些是待實測的工程目標，不是已達成數字。
- 真機驗證飛航模式、無可用語音、重裝、資料升級、大字體、返回鍵、中文鍵盤與低儲存空間。已通過的測試只在新變更或新問題相關時重跑。
